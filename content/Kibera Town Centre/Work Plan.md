# Convert static descriptions, plans, or state descriptions to dynamic executable models
## Design Pattern
### Find, build, or sketch descriptions of systems
	- Kibera Town Centre working drawings; spreadsheets itemizing all elements in clean water treatment system; elements in waste water treatment; elements in power design; elements in tank systems

### Pass descriptions through Google Notebook; query to extract alternative descriptive forms
- Jupyter notebooks for each system, structure, or element: develop executable code for each component, with sensor and data inputs, state transition descriptions, and resultant state
- "*There is at any instant exactly one physically possible future*"[^1]
- Similar to hardware design languages, with provability sequences
- Use LEAN proof methodology 
- Use Colorado School of Mines  [[Bricks]] [ontology](https://cs.mines.edu/project/fierro-gabriel/) , developed at UC Berkeley by [[Gabe Fierro]]
